Часть 1. Архитектура: как React общается с Django

1.1 Что такое SPA и чем отличается от серверного рендеринга

[DOC] React: Quick Start · MDN: SPA

SPA (Single Page Application) — это веб-приложение, которое загружает одну HTML-страницу, а потом динамически обновляет её содержимое без перезагрузки. React — это SPA-фреймворк.

Традиционный подход (Django templates):

Пользователь кликает «Каталог» → Браузер отправляет GET /catalog/ → Django рендерит HTML на сервере → Браузер ПОЛНОСТЬЮ перезагружает страницу → Пользователь видит каталог Время:Время: 300–800мс (полная перезагрузка) НЕТ Теряется состояние: скролл, открытые меню, введённый текст

SPA-подход (React):

Пользователь кликает «Каталог» → React меняет URL на /products (БЕЗ перезагрузки!) → React отправляет GET /api/v1/catalog/products/ → Django возвращает JSON (не HTML!) → React рисует каталог из JSON Время:Время: 50–150мс (только данные, без HTML/CSS/JS) ДА Состояние сохраняется: скролл, меню, текст
АспектDjango TemplatesReact SPA
Кто рисует HTML?Сервер (Python)Браузер (JavaScript)
Что возвращает сервер?Готовый HTMLЧистый JSON
НавигацияПолная перезагрузкаБез перезагрузки
СкоростьМедленнееБыстрее
SEOОтличноНужно SSR (Next.js)
СложностьПрощеСложнее (2 проекта)
[!] Важно понимать

Django и React — это два отдельных проекта, которые общаются через HTTP-запросы (API). Django не знает о React, React не знает о Django. Единственная связь — это JSON, который летает между ними по сети.

1.3 JWT-авторизация: как работает токенный доступ

[DOC] SimpleJWT · jwt.io

JWT (JSON Web Token) — это способ авторизации без сессий. Вместо хранения сессии на сервере, браузер хранит токен — зашифрованную строку, которая доказывает «я — этот пользователь».

Два токена

ТокенВремя жизниГде хранитсяЗачем
access15 минутlocalStorageПрикрепляется к каждому запросу
refresh7 днейlocalStorageПолучить новый access без повторного логина

Жизненный цикл JWT

1. ПОЛЬЗОВАТЕЛЬ ВВОДИТ EMAIL + ПАРОЛЬ │ ▼ 2. REACT ОТПРАВЛЯЕТ POST /api/v1/auth/login/ {"email": "user@mail.com", "password": "secret123"} │ ▼ 3. DJANGO ПРОВЕРЯЕТ ПАРОЛЬ → возвращает: {"access": "eyJhbG...", "refresh": "eyJhbG..."} │ ▼ 4. REACT СОХРАНЯЕТ ТОКЕНЫ В localStorage localStorage.setItem('access_token', data.access) localStorage.setItem('refresh_token', data.refresh) │ ▼ 5. КАЖДЫЙ СЛЕДУЮЩИЙ ЗАПРОС: GET /api/v1/users/me/ Header: Authorization: Bearer eyJhbG... │ ▼ 6. ЕСЛИ ACCESS УСТАРЕЛ (15 мин) → сервер вернёт 401 │ ▼ 7. REACT АВТОМАТИЧЕСКИ ОТПРАВЛЯЕТ: POST /api/v1/auth/refresh/ {"refresh": "eyJhbG..."} │ ▼ 8. DJANGO ВЫДАЁТ НОВЫЙ ACCESS: {"access": "eyJNEW..."} │ ▼ 9. REACT ПОВТОРЯЕТ ОРИГИНАЛЬНЫЙ ЗАПРОС С НОВЫМ ТОКЕНОМ (пользователь ничего не замечает!)
⚠️ Почему два токена?

Если хакер украдёт access — он сможет пользоваться им только 15 минут. refresh используется редко (раз в 15 мин), его легче защитить. Это как с банковской картой: основная карта (access) — для ежедневных покупок, а запасная (refresh) — хранится дома и используется только для перевыпуска основной.

Что хранится внутри JWT-токена?

// Access token (расшифрованный):
{
  "token_type": "access",
  "exp": 1718300000,       // когда истекает (Unix timestamp)
  "iat": 1718299100,       // когда создан
  "jti": "abc123...",      // уникальный ID токена
  "user_id": 42            // ID пользователя в Django
}

// Django проверяет: токен не истёк? подпись верна? → user_id = 42

1.4 CORS: почему браузер блокирует запросы и как это исправить

[DOC] django-cors-headers · MDN: CORS

CORS (Cross-Origin Resource Sharing) — это механизм безопасности браузера. По умолчанию браузер запрещает JavaScript-коду с одного домена делать запросы к другому домену.

БЕЗ CORS: React (localhost:5173) ──XHR──▶ Django (localhost:8000) │ НЕТ Браузер блокирует! Разные порты = разные origins! С CORS: React (localhost:5173) ──XHR──▶ Django (localhost:8000) │ Django отвечает с заголовком: Access-Control-Allow-Origin: http://localhost:5173 │ ДА Браузер видит заголовок → разрешает!

Как CORS настроен в нашем Django

# config/settings.py

# 1. Приложение corsheaders добавлено в INSTALLED_APPS
INSTALLED_APPS = [
    ...
    "corsheaders",  # ← Это!
]

# 2. Middleware ДО CommonMiddleware
MIDDLEWARE = [
    "corsheaders.middleware.CorsMiddleware",  # ← ДО!
    "django.middleware.common.CommonMiddleware",
    ...
]

# 3. Настройки CORS
CORS_ALLOW_ALL_ORIGINS = True  # В DEBUG = True (разрешить всем)
CORS_ALLOWED_ORIGINS = [
    "http://localhost:3000",   # CRA
    "http://localhost:5173",   # Vite ← наш фронтенд
]
CORS_ALLOW_CREDENTIALS = True   # Разрешить куки + JWT-заголовки
CORS_ALLOW_HEADERS = [
    "authorization",  # ← JWT-токен!
    "content-type",
    ...
]
[!!] Частая ошибка

Если CorsMiddleware стоит ПОСЛЕ CommonMiddleware, CORS не работает! Порядок middleware в Django имеет значение. Наш проект уже настроен правильно — не меняй порядок.

1.5 Vite proxy: зачем и как перенаправлять запросы

[DOC] Vite: Server Options

Без proxy тебе пришлось бы писать полный URL в каждом запросе:

// НЕТ Без proxy — приходится указывать полный URL
axios.get('http://localhost:8000/api/v1/catalog/products/')

С proxy Vite автоматически перенаправляет запросы:

// ДА С proxy — короткий и красивый URL
axios.get('/api/v1/catalog/products/')
// Vite сам подставит http://localhost:8000

Как это работает

Браузер (localhost:5173) │ │ GET /api/v1/catalog/products/ │ ▼ Vite Dev Server (localhost:5173) │ видит: путь начинается с /api │ proxy: /api → http://localhost:8000 │ ▼ Django (localhost:8000) │ GET /api/v1/catalog/products/ │ обрабатывает → возвращает JSON │ ▼ Vite Dev Server │ пересылает JSON обратно браузеру │ ▼ React получает JSON ДА
ДА Proxy работает ТОЛЬКО в dev-режиме

Когда ты запускаешь npm run dev, Vite проксирует запросы. В production (после npm run build) proxy не работает — nginx должен сам перенаправлять /api/* на Django.

3.4 Настройка Vite proxy

[DOC] Vite config

Proxy — это «пересылка» запросов. Когда React делает запрос на /api/v1/..., Vite автоматически пересылает его на Django (localhost:8000).

4 Замени содержимое vite.config.ts 
// vite.config.ts
// Конфигурация сборщика Vite.
// proxy — перенаправляет API-запросы на Django.

import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  // Плагин для React (JSX-трансформация)
  plugins: [react()],

  server: {
    // Порт фронтенд-сервера
    port: 5173,

    // Proxy — автоматическое перенаправление запросов
    proxy: {
      // Все запросы, начинающиеся с /api → пересылаются на Django
      '/api': {
        target: 'http://localhost:8000',  // Адрес Django
        changeOrigin: true,  // Подменять Host-заголовок
        // НЕ пишем rewrite — пути совпадают!
      },

      // Media-файлы (картинки товаров, аватары)
      '/media': {
        target: 'http://localhost:8000',
        changeOrigin: true,
      },
    },
  },
})

Почему это работает

React: axios.get('/api/v1/catalog/products/') │ ▼ Vite (port 5173): видит /api → proxy │ ▼ Django (port 8000): GET /api/v1/catalog/products/ │ ▼ Django возвращает JSON │ ▼ Vite пересылает JSON в React ДА
⚠️ Django должен быть запущен!

Proxy только перенаправляет запросы. Если Django не запущен (python manage.py runserver), Vite вернёт ошибку ECONNREFUSED.

Часть 4. API-клиент (axios + JWT)

Это самый важный файл всего фронтенда. Он отвечает за ВСЕ запросы к Django. Если он правильно настроен, остальные файлы просто вызывают api.get(...) и api.post(...) — без мыслей о токенах.

4.1 Создание экземпляра axios

[DOC] Axios Instance · Axios Interceptors
5 Создай файл src/api/client.ts 
// src/api/client.ts
// Единый HTTP-клиент для всех запросов к Django-бэкенду.
// 
// ЧТО ДЕЛАЕТ ЭТОТ ФАЙЛ:
//   1. Создаёт экземпляр axios с базовым URL /api/v1
//   2. Автоматически подставляет JWT-токен в каждый запрос (request interceptor)
//   3. При получении 401 (токен истёк) — автоматически обновляет токен
//      и повторяет запрос (response interceptor)
//
// КАК ИСПОЛЬЗОВАТЬ:
//   import api from '../api/client';
//   const response = await api.get('/catalog/products/');
//   const response = await api.post('/auth/login/', { email, password });
//
// ПОЧЕМУ НЕ ПРОСТО axios.get():
//   - Нужно вручную добавлять Authorization-заголовок в КАЖДЫЙ запрос
//   - Нет авто-refresh при истёкшем токене
//   - Нет единого базового URL

import axios from 'axios';

// Базовый URL — все запросы будут начинаться с /api/v1/
// Vite proxy перенаправит /api/v1/* → http://localhost:8000/api/v1/*
const API_BASE = '/api/v1';

// ─── СОЗДАЁМ ЭКЗЕМПЛЯР AXIOS ───
// Зачем create(), а не просто axios? 
// Чтобы настройки (baseURL, заголовки) применялись ко ВСЕМ запросам.
const api = axios.create({
  baseURL: API_BASE,
  headers: {
    'Content-Type': 'application/json',
  },
});

// ─── REQUEST INTERCEPTOR: подставляем JWT ───
// Интерцептор = функция, которая ВСТРАИВАЕТСЯ между вызовом api.get()
// и фактической отправкой запроса.
// 
// Схема:
//   api.get('/users/me/') 
//     → interceptor добавляет Authorization-заголовок
//     → запрос отправляется на сервер
//
// Без интерцептора пришлось бы писать:
//   api.get('/users/me/', {
//     headers: { Authorization: `Bearer ${token}` }  // КАЖДЫЙ РАЗ!
//   })

api.interceptors.request.use(
  (config) => {
    // Читаем access-токен из localStorage
    const token = localStorage.getItem('access_token');
    
    if (token) {
      // Добавляем заголовок: Authorization: Bearer eyJhbG...
      config.headers.Authorization = `Bearer ${token}`;
    }
    
    // Обязательно возвращаем config — иначе запрос не отправится!
    return config;
  },
  (error) => {
    // Если ошибка ДО отправки запроса (маловероятно, но бывает)
    return Promise.reject(error);
  }
);

// ─── RESPONSE INTERCEPTOR: авто-refresh при 401 ───
// Если сервер вернул 401 Unauthorized — значит access-токен истёк (15 мин).
// Мы автоматически:
//   1. Отправляем refresh-токен на /auth/refresh/
//   2. Получаем новый access-токен
//   3. Повторяем оригинальный запрос с новым токеном
// Пользователь ничего не замечает!

api.interceptors.response.use(
  // Если ответ успешный (2xx) — просто пропускаем
  (response) => response,

  // Если ошибка (4xx, 5xx) — проверяем, не истёк ли токен
  async (error) => {
    const originalRequest = error.config;

    // Проверяем: это 401 И мы ещё НЕ пробовали refresh
    // _retry — наш флаг, чтобы не зациклиться
    if (
      error.response?.status === 401 &&
      !originalRequest._retry &&
      !originalRequest.url?.includes('/auth/login/')  // Не refresh'им при логине!
    ) {
      originalRequest._retry = true;  // Помечаем: уже пробуем refresh

      const refreshToken = localStorage.getItem('refresh_token');
      
      if (refreshToken) {
        try {
          // Запрашиваем новый access-токен
          // Используем ПРЯМОЙ axios (не api!), чтобы не зациклить интерцептор
          const { data } = await axios.post(`${API_BASE}/auth/refresh/`, {
            refresh: refreshToken,
          });

          // Сохраняем новый access-токен
          localStorage.setItem('access_token', data.access);

          // Если бэкенд вернул новый refresh (ROTATE_REFRESH_TOKENS=True)
          if (data.refresh) {
            localStorage.setItem('refresh_token', data.refresh);
          }

          // Обновляем заголовок в оригинальном запросе
          originalRequest.headers.Authorization = `Bearer ${data.access}`;
          
          // Повторяем оригинальный запрос с новым токеном
          return api(originalRequest);
          
        } catch (refreshError) {
          // Refresh-токен тоже истёк (7 дней) — полный логаут
          localStorage.removeItem('access_token');
          localStorage.removeItem('refresh_token');
          
          // Перенаправляем на страницу входа
          window.location.href = '/login';
          return Promise.reject(refreshError);
        }
      } else {
        // Нет refresh-токена — пользователь не авторизован
        window.location.href = '/login';
      }
    }

    // Для всех остальных ошибок — просто передаём дальше
    return Promise.reject(error);
  }
);

// Экспортируем — все остальные файлы будут использовать api.get(), api.post()
export default api;
[!!] Почему axios.post(), а не api.post() при refresh?

В строке const { data } = await axios.post(`${API_BASE}/auth/refresh/`, ...) мы используем прямой axios, а не наш api. Причина: если использовать api, сработает request-интерцептор, который подставит старый (истёкший) access-токен. А нам нужно отправить ТОЛЬКО refresh-токен в теле, без access-заголовка.

4.4 Файл endpoints.ts — все URL в одном месте

6 Создай файл src/api/endpoints.ts 
// src/api/endpoints.ts
// Все пути к API-эндпоинтам в одном файле.
// 
// ПОЧЕМУ НЕ ПИСАТЬ URL ПРЯМО В КОДЕ:
//   Если на бэкенде изменится URL (например, /cart/ → /shopping-cart/),
//   придётся искать и менять его в 20 местах.
//   С endpoints.ts — меняем только здесь, в одном месте.
//
// КАК ИСПОЛЬЗОВАТЬ:
//   import { AUTH, CATALOG } from '../api/endpoints';
//   api.post(AUTH.LOGIN, { email, password });
//   api.get(CATALOG.PRODUCTS, { params: { search: 'iphone' } });
//   api.get(CATALOG.PRODUCT('iphone-15-pro'));
//

Часть 5. Глобальное состояние (Zustand)

5.1 Что такое Zustand и зачем он нужен

[DOC] Zustand GitHub

В React у каждого компонента есть свой локальное состояние (useState). Но некоторые данные нужны во многих местах:

  • Пользователь — нужен в хедере, на странице профиля, при оформлении заказа
  • Корзина — нужна в хедере (количество товаров), на странице корзины, при добавлении товара
  • Уведомления — нужны в хедере (колокольчик), на странице уведомлений

Zustand — это «глобальная переменная» для React. Любой компонент может прочитать или изменить данные.

// src/stores/authStore.ts
// Глобальное хранилище пользователя.
// Zustand — простой state manager (замена Redux/Context).
//
// ЧТО ХРАНИТСЯ:
//   - user: объект пользователя (null если не авторизован)
//   - isLoading: загружается ли профиль (показываем спиннер)
//   - isAuthenticated: авторизован ли пользователь
//
// ДЕЙСТВИЯ:
//   - login(email, password) — вход, получение JWT
//   - register(data) — регистрация + автологин
//   - logout() — очистка токенов
//   - fetchUser() — получить профиль при загрузке приложения

import { create } from 'zustand';
import api from '../api/client';
import { AUTH, USER } from '../api/endpoints';

// ─── TypeScript-типы ───

interface UserProfile {
  timezone: string;
  language: string;
  avatar: string | null;
}

interface User {
  id: number;
  email: string;
  username: string;
  first_name: string;
  last_name: string;
  phone: string;
  profile: UserProfile | null;
}

interface RegisterData {
  email: string;
  username: string;
  password: string;
  password_confirm: string;
  first_name?: string;
  last_name?: string;
}

interface AuthState {
  // ─── Состояние (данные) ───
  user: User | null;
  isLoading: boolean;
  isAuthenticated: boolean;

  // ─── Действия (функции, меняющие состояние) ───
  login: (email: string, password: string) => Promise<void>;
  register: (data: RegisterData) => Promise<void>;
  logout: () => void;
  fetchUser: () => Promise<void>;
}

// ─── Store ───
// create() принимает функцию (set, get) => ({...state, ...actions})
// set() — обновляет состояние (как this.setState в классовых компонентах)
// get() — читает текущее состояние

export const useAuthStore = create<AuthState>((set, get) => ({
  // Начальное состояние:
  user: null,
  isLoading: true,          // true — при первой загрузке проверяем токен
  isAuthenticated: false,

  // ─── LOGIN ───
  // Шаг 1: POST /auth/login/ → получаем {access, refresh}
  // Шаг 2: Сохраняем токены в localStorage
  // Шаг 3: GET /users/me/ → получаем профиль пользователя
  // Шаг 4: Обновляем состояние
  login: async (email, password) => {
    // ① Получаем JWT-токены
    const { data } = await api.post(AUTH.LOGIN, { email, password });

    // ② Сохраняем в localStorage (для интерцептора)
    localStorage.setItem('access_token', data.access);
    localStorage.setItem('refresh_token', data.refresh);

    // ③ Получаем профиль пользователя
    const { data: user } = await api.get(USER.ME);

    // ④ Обновляем глобальное состояние
    set({
      user,
      isAuthenticated: true,
      isLoading: false,
    });
  },

  // ─── REGISTER ───
  // Регистрация + автоматический вход
  register: async (registerData) => {
    // ① Создаём аккаунт
    await api.post(AUTH.REGISTER, registerData);

    // ② Автоматически логинимся
    // get() — читаем текущее состояние (нужен для доступа к login)
    await get().login(registerData.email, registerData.password);
  },

  // ─── LOGOUT ───
  logout: () => {
    // Удаляем токены
    localStorage.removeItem('access_token');
    localStorage.removeItem('refresh_token');

    // Сбрасываем состояние
    set({
      user: null,
      isAuthenticated: false,
      isLoading: false,
    });
  },

  // ─── FETCH USER ───
  // Вызывается при первой загрузке приложения.
  // Если в localStorage есть токен — проверяем, валидный ли он.
  fetchUser: async () => {
    const token = localStorage.getItem('access_token');
    
    // Нет токена — не авторизован
    if (!token) {
      set({ isLoading: false });
      return;
    }

    try {
      // Пробуем получить профиль
      const { data } = await api.get(USER.ME);
      set({
        user: data,
        isAuthenticated: true,
        isLoading: false,
      });
    } catch {
      // Токен невалидный (истёк + refresh не помог) — чистим
      localStorage.removeItem('access_token');
      localStorage.removeItem('refresh_token');
      set({
        user: null,
        isAuthenticated: false,
        isLoading: false,
      });
    }
  },
}));

// src/stores/cartStore.ts
// Глобальное хранилище корзины.
//
// ЧТО ХРАНИТСЯ:
//   - cart: объект корзины с товарами (null = не загружена)
//   - isCartOpen: открыта ли боковая панель корзины
//   - isLoading: загружается ли
//
// ДЕЙСТВИЯ:
//   - fetchCart() — получить корзину с сервера
//   - addItem(variantId, quantity) — добавить товар
//   - updateItem(itemId, quantity) — изменить количество
//   - removeItem(itemId) — удалить позицию
//   - clearCart() — очистить корзину
//   - toggleCart() — открыть/закрыть боковую панель

import { create } from 'zustand';
import api from '../api/client';
import { CART } from '../api/endpoints';

// ─── Типы ───

interface CartItem {
  id: number;
  variant_id: number;
  product_name: string;
  sku: string;
  unit_price: string;
  quantity: number;
  total_price: string;
  image: string | null;
}

interface Cart {
  id: number;
  items: CartItem[];
  total_quantity: number;
  total_price: string;
}

interface CartState {
  cart: Cart | null;
  isCartOpen: boolean;
  isLoading: boolean;

  fetchCart: () => Promise<void>;
  addItem: (variantId: number, quantity?: number) => Promise<void>;
  updateItem: (itemId: number, quantity: number) => Promise<void>;
  removeItem: (itemId: number) => Promise<void>;
  clearCart: () => Promise<void>;
  toggleCart: () => void;
}

export const useCartStore = create<CartState>((set, get) => ({
  cart: null,
  isCartOpen: false,
  isLoading: false,

  // ─── Получить корзину ───
  fetchCart: async () => {
    try {
      const { data } = await api.get(CART.CART);
      set({ cart: data });
    } catch {
      // Гостевая корзина может не существовать — это нормально
    }
  },

  // ─── Добавить товар в корзину ───
  // После добавления сервер возвращает обновлённую корзину
  addItem: async (variantId, quantity = 1) => {
    set({ isLoading: true });
    try {
      const { data } = await api.post(CART.ITEMS, {
        variant_id: variantId,
        quantity,
      });
      set({ cart: data, isLoading: false });
      // Автоматически открываем боковую панель корзины
      set({ isCartOpen: true });
    } catch (error) {
      set({ isLoading: false });
      throw error; // Пробрасываем ошибку для отображения в UI
    }
  },

  // ─── Изменить количество ───
  updateItem: async (itemId, quantity) => {
    set({ isLoading: true });
    try {
      const { data } = await api.patch(CART.ITEM(itemId), { quantity });
      set({ cart: data, isLoading: false });
    } catch (error) {
      set({ isLoading: false });
      throw error;
    }
  },

  // ─── Удалить позицию ───
  removeItem: async (itemId) => {
    set({ isLoading: true });
    try {
      const { data } = await api.delete(CART.ITEM(itemId));
      set({ cart: data, isLoading: false });
    } catch (error) {
      set({ isLoading: false });
      throw error;
    }
  },

  // ─── Очистить корзину ───
  clearCart: async () => {
    const { data } = await api.delete(CART.CART);
    set({ cart: data });
  },

  // ─── Открыть/закрыть боковую панель ───
  toggleCart: () => set((state) => ({ isCartOpen: !state.isCartOpen })),
}));

// src/stores/notificationStore.ts
// Глобальное хранилище уведомлений.
// Отображается в хедере (колокольчик с бейджем).

import { create } from 'zustand';
import api from '../api/client';
import { NOTIFICATION } from '../api/endpoints';

interface Notification {
  id: number;
  type: string;           // order_created, payment_success, etc.
  title: string;
  message: string;
  is_read: boolean;
  created_at: string;
}

interface NotificationState {
  notifications: Notification[];
  unreadCount: number;
  isLoading: boolean;

  fetchNotifications: () => Promise<void>;
  fetchUnreadCount: () => Promise<void>;
  markRead: (id: number) => Promise<void>;
  markAllRead: () => Promise<void>;
}

export const useNotificationStore = create<NotificationState>((set) => ({
  notifications: [],
  unreadCount: 0,
  isLoading: false,

  fetchNotifications: async () => {
    set({ isLoading: true });
    const { data } = await api.get(NOTIFICATION.LIST);
    set({ notifications: data.results || data, isLoading: false });
  },

  fetchUnreadCount: async () => {
    const { data } = await api.get(NOTIFICATION.UNREAD_COUNT);
    set({ unreadCount: data.count || data.unread_count || 0 });
  },

  markRead: async (id) => {
    await api.post(NOTIFICATION.MARK_READ(id));
    // Обновляем локально (без нового запроса)
    set((state) => ({
      notifications: state.notifications.map(n =>
        n.id === id ? { ...n, is_read: true } : n
      ),
      unreadCount: Math.max(0, state.unreadCount - 1),
    }));
  },

  markAllRead: async () => {
    await api.post(NOTIFICATION.READ_ALL);
    set((state) => ({
      notifications: state.notifications.map(n => ({ ...n, is_read: true })),
      unreadCount: 0,
    }));

// Компонент-обёртка для защищённых страниц.
// Если пользователь не авторизован → перенаправляем на /login.
//
// КАК РАБОТАЕТ:
//   <ProtectedRoute>
//     <ProfilePage />    ← отрендерится ТОЛЬКО если авторизован
//   </ProtectedRoute>
//
// Аналог в Django: @login_required декоратор

import { Navigate, Outlet } from 'react-router-dom';
import { useAuthStore } from '../stores/authStore';

export function ProtectedRoute() {
  const { isAuthenticated, isLoading } = useAuthStore();

  // Если профиль ещё загружается — показываем спиннер
  if (isLoading) {
    return (
      <div style={{ 
        display: 'flex', 
        justifyContent: 'center', 
        alignItems: 'center', 
        height: '50vh' 
      }}>
        <div style={{ fontSize: '24px' }}>... Загрузка...</div>
      </div>
    );
  }

  // Не авторизован → редирект на /login
  // replace — чтобы кнопка «Назад» не вернула на защищённую страницу
  if (!isAuthenticated) {
    return <Navigate to="/login" replace />;
  }

  // Авторизован → рендерим дочерние маршруты
  // Outlet — это «дырка», куда React Router вставит дочернюю страницу
  return <Outlet />;
}

7.3 Автовход при обновлении страницы

Когда пользователь обновляет страницу, React «забывает» всё состояние (включая user из authStore). Но JWT-токены всё ещё лежат в localStorage!

В Layout.tsx мы уже вызываем fetchUser() при загрузке. Давай разберём, как это работает:

Пользователь обновляет страницу (F5) │ ▼ React перезагружается. authStore: user=null, isAuthenticated=false │ ▼ Layout.tsx → useEffect → fetchUser() │ ▼ fetchUser() проверяет localStorage: - access_token есть? → ДА │ ▼ GET /api/v1/users/me/ Authorization: Bearer eyJhbG...старый_access │ ▼ Два варианта: ┌─────────────────────────────────────────────────┐ │ А) access ещё валиден (15 мин не прошло) │ │ → Django возвращает профиль │ │ → isAuthenticated = true ДА │ │ │ │ Б) access истёк (15 мин прошло) │ │ → Django возвращает 401 │ │ → Response interceptor: POST /auth/refresh/ │ │ → Получаем новый access │ │ → Повторяем GET /users/me/ с новым токеном │ │ → isAuthenticated = true ДА │ └─────────────────────────────────────────────────┘
⚠️ Важный момент

В первые миллисекунды после загрузки isAuthenticated = false, а isLoading = true. Поэтому ProtectedRoute показывает спиннер, а не перенаправляет на /login. Когда fetchUser завершается, isLoading становится false, и страница показывается.

Шаг 1: Собери React

cd frontend
npm run build
# Создаётся папка dist/ с оптимизированными файлами

Шаг 2: Настрой Nginx

# /etc/nginx/sites-available/amazone

server {
    listen 80;
    server_name amazone.com;

    # React (собранные файлы)
    location / {
        root /var/www/amazone/frontend/dist;
        try_files $uri $uri/ /index.html;  # SPA: все маршруты → index.html
    }

    # Django API
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # Django media
    location /media/ {
        proxy_pass http://127.0.0.1:8000;
    }

    # Django static (admin, etc.)
    location /static/ {
        proxy_pass http://127.0.0.1:8000;
    }
}
