## 3. Архитектурная структура (кратко)

Backend: Django-проект (`config/`, `apps/`), DRF, PostgreSQL (единственная поддерживаемая БД), Redis + Celery.

Приложения под `apps/`:

- `core`, `users`, `catalog`, `inventory`, `pricing`, `cart`, `orders`, `payments`, `reviews`, `discounts`, `shipping`, `wishlist`, `notifications`, `analytics`.

Ключевые архитектурные правила, зафиксированные в документации:

- `View → Serializer → Service → ORM`; бизнес-логика — в сервисах.
- Каждое приложение владеет своими моделями; мутации через сервис владельца.
- Междоменные побочные эффекты — через явные сервисные вызовы в транзакциях.
- Concurrency-sensitive состояния — `select_for_update()` и `transaction.atomic`.
- `pricing → catalog` — однонаправленная зависимость для `Product.min_price` / `max_price`.
- Cross-domain Django-сигналы — legacy/tech debt; для новых междоменных workflow не вводить.

Сведения в этом разделе отражают содержание документов проекта. Отдельная сверка документации с фактическим кодом всех модулей в рамках данного аудита не проводилась.
